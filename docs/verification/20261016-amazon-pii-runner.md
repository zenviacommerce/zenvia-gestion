## Delivered behavior

CLI 2.121.0 generated additive migration `20261016194728_amazon_pii_bounded_runner.sql`. It creates no scheduled job and updates no existing rows. Public RPCs are revoked from PUBLIC/anon/authenticated and granted only to service_role; their private gate/receipt tables have RLS and no ordinary-client privileges. SECURITY DEFINER is deliberate for these service-only, statically qualified, owner-scoped backend operations.

`amazon_pii_run_batch(owner,run_id,mode,limit,dry_run)` defaults to a read-only pilot preview. An empty private execution gate blocks writes until reconciliation, complete cycle, deployed guard/consumer review and copy inventory review are recorded. Pilot is exactly ten canonical owner+Amazon references, deterministically ordered by purchase date then reference. All duplicate fulfillment rows of a selected reference are redacted in the same transaction. Missing purchase, young duplicates, conflicting identities and active order/tracking action leases do not become candidates. No status or fiscal exception. With no verified delivery timestamp/provenance in production, this implementation explicitly uses purchase+1440 hours; it never treats fulfilled_at/DELIVERED as delivery proof. The existing shared deadline supports verified delivery+720 hours once an actual trusted source is established; this runner does not invent one.

First write pilot sets pilot_run_id; a different second pilot is blocked. Same owner/run_id/mode/limit retries return the original safe receipt. Batch mode is blocked until pilot_verified_at is explicitly recorded after production UI checks. Remaining calls permit 1–50 canonical orders and at most500 duplicate rows per transaction. A transaction-scoped advisory owner lease prevents concurrent purgers; per-order fences serialize ingestion against tombstones. SKIP LOCKED detects busy candidate rows and fails the entire batch rather than partially purging a canonical order or silently shrinking the pilot. Every call has a3s statement budget and500ms lock budget. Failure rolls back buyer changes, tombstones, pilot marker and receipt. No PII error text is persisted by the runner; caller must log only SQLSTATE/stable error code, not arbitrary driver error/parameters.

Receipts contain run_id, policy version, evaluation time, mode, counts, skipped-reason counts, table counts, opaque cohort fingerprint and duration; no buyer fields or order list. Dry-run makes no writes, leases, external requests or Storage operations. Its selection function is identical to write mode; concurrent source changes can change the subsequent candidate set, so repeat preview immediately before execution and review counts. A full purge is never implied by a successful fulfillment receipt.

The existing final fulfillment guard clears customer columns, addresses, entire raw_payload (including historical buyer, recipient fallback and tracking-event JSON), personalization/free text and label/tracking capability columns, projecting items to IDs/SKU/quantity/money. New final capability guard also replaces NOT NULL legacy `sendcloud_id` with `amazon-purged:<row UUID>` and clears `shopify_tracking_synced_number`. Production metadata/counts showed862numeric external IDs among959Amazon rows; keeping that identifier would have retained a retrieval capability. The synthetic importer uses canonical order_number to find existing rows; the full real page importer test proves later imports preserve normalized economic facts while database guards prevent operational rehydration.

Every Amazon write now rejects two conflicting valid canonical references before any marker early return. A review regression demonstrated the previous bypass (fresh order_number plus tombstoned order_id); INSERT/UPDATE in both directions now fail closed. No historical invalid row is rewritten by migration.

`amazon_pii_scrub_control_copies(owner,limit,dry_run)` is a separately reviewed minimization step, bounded to at most50 rows per each of jobs/runs/state. It preserves typed mode/snapshot/high-water/superseded controls and typed last_job_id/row/queued counts; removes arbitrary nested payloads/checkpoints and replaces error text with AMAZON_SYNC_ERROR. Diagnostics such as reason/recovery/image_sync/image_sync_error are deliberately removed, not needed by worker selection/retry. New insert/update guards enforce this projection immediately. Historical rows remain unchanged until explicitly scrubbed. Order purge refuses to proceed while these owner-scoped historical controls are unsafe. Nothing touches invoices, supplier/customer documents, finance/audit/support tables or Storage.
